1. Objetivo del documento

Especificar los requisitos funcionales y no funcionales de la plataforma web LexOnline: qué debe poder hacer el usuario (agendar consultas, inscribirse a cursos, contactarse, conectarse a la sala virtual), cómo debe comportarse el sistema ante cada interacción y qué criterios de calidad debe cumplir la entrega.

Estado: este documento se encuentra en elaboración. Mientras tanto, el detalle funcional de cada flujo puede revisarse en las fichas de proceso P01–P07 del DP-01 · Documento de Procesos, que describen paso a paso el comportamiento actual de la plataforma.

2. Modelo de datos vigente

Todo el catálogo de la plataforma vive en un único archivo: js/datos.js, que expone el objeto global LEX. El modelo aplica el principio de una sola fuente de verdad: cada entidad se define una vez con su id, y las demás entidades la referencian por ese identificador — nunca duplicando nombres.

2.3 Validador automático de integridad

Al cargar la página, js/main.js invoca LEX.validarLex(), que verifica: ids únicos por colección, que todo abogadoId, docenteId y productoId exista, que ninguna especialidad quede sin abogados y que los precios sean mayores a cero. Los problemas se reportan en la consola del navegador sin interrumpir el sitio.

2.4 Guía operativa: cómo actualizar el catálogo

  1. Agregar un abogado: añadir su objeto a LEX.abogados con un id nuevo (aparece solo en la sección Staff).
  2. Asignarlo a una especialidad: agregar ese id al array abogadosIds de la especialidad correspondiente.
  3. Crear un curso: añadir objeto a LEX.cursos usando un docenteId existente.
  4. Registrar enlace de pago (fase 2): agregar { id, nombre, url, productoId } a pagos.enlacesOnline; los botones "Pagar" aparecen automáticamente.
  5. Verificar: recargar la web; si la consola no muestra avisos, el catálogo quedó íntegro. Las estadísticas de la portada se recalculan solas.

Anexo · Activación del pago online directo (fase 2)

Actualmente los pagos se coordinan por WhatsApp (Yape, Plin o transferencia) una vez confirmada la cita o inscripción, según la sección "Cómo pagar" de la web. Por seguridad, no se publican números ni códigos QR en la plataforma.

La plataforma ya tiene preparado el módulo de pago online directo. Para activarlo cuando el estudio disponga de su cuenta de pasarela (Mercado Pago, Culqi o Izipay), seguir estos pasos:

  1. Crear la cuenta empresa en la pasarela elegida y completar la validación KYC con los datos del titular del negocio.
  2. Generar un enlace de pago por cada producto que se cobre automáticamente (cada especialidad de consulta y cada curso del catálogo).
  3. Registrar los enlaces en js/datos.js, dentro de LEX.pagos.enlacesOnline, con el formato { nombre: "Derecho Penal", url: "https://mpago.la/..." }.
  4. Publicar los cambios: la sección "Cómo pagar" renderizará automáticamente un botón "Pagar" por cada enlace, y el badge pasará de "próximamente" a "Pago online directo disponible". No se requiere tocar HTML ni JS adicional.
  5. Opcional: comunicar a Cal.com/WhatsApp el flujo para enviar el comprobante de pasarela en lugar de la captura manual.
Criterio de aceptación fase 2: con al menos un enlace registrado, el visitante puede pagar desde la web sin coordinación previa; el administrador recibe la notificación de la pasarela y confirma el acceso (link Meet / material del curso).
